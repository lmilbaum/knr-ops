# Centralize Project Dependency Version Pins (issue #62) Implementation Plan

> **For Hermes:** Use subagent-driven development to implement this plan task-by-task. Each PR section below is one self-contained subagent dispatch with exact files, gates, and commit/PR instructions.

**Goal:** One authoritative, human-reviewable dependency catalog (`deps/versions.toml`) that every version consumer in knr-ops is either generated from or validated against, delivered incrementally as six small PRs.

**Architecture:** A TOML catalog defines logical dependencies and their pinned versions. A slot engine validates that every literal occurrence in the repo matches the catalog, and a forbid pass asserts pins appear only in allowed files. Scripts consume the catalog directly through a bash-sourceable env file (awk-parsed, no Python needed on gap-side hosts). `zarf.yaml` and `airgap/images.txt` become generated files rendered from `.in` templates with a `--check` drift mode. Kubernetes manifests and CI workflows keep literal pins enforced by validation, because Flux-synced YAML and GitHub Actions cannot read external files at runtime.

**Tech stack:** bash, awk, Python 3.11+ (stdlib `tomllib` only, via mise-pinned python), TOML, existing mise tasks, existing GitHub Actions.

**Repo:** `/Users/shrinedogg/knr-ops` (origin `polarsquad/knr-ops`, fork remote `lmilbaum/knr-ops` exists but is NOT used for this work: the konflate CI skips fork PRs by design, so all branches push to origin).

### Slot validation: `deps/scripts/check.py`

Slots live in the catalog as `[[slot]]` arrays keyed by file:

```toml
[[slot]]
key = "capi"                                    # references versions.capi
file = "mgmt/local-host/capi-providers/capi-system/providers.yaml"
pattern = 'version: "v{version}"'
count = 3
```

`check.py` semantics (stdlib only: `tomllib`, `re`, `pathlib`, `argparse`):

1. Load `deps/versions.toml`.
2. For each `[[slot]]`: build a regex by regex-escaping the pattern and replacing `{version}` with the re-escaped resolved value; count matches in the file; fail with file, key, expected count, actual count.
3. A version bump that forgets a consumer makes the old-version pattern match zero times: the slot fails. A consumer edit that forgets the catalog fails the same way.
4. `--forbid` mode (activated family by family, see PRs): for every `[versions]` and `[images]` key, grep the repo (excluding `deps/`, `docs/` allowlist, `.git/`, gitignored `airgap/{archives,rendered,sbom,config-artifact}/`, `*.sops.yaml`) for the resolved literal; any hit in a file without a slot for that key is an error. This is the end-state single-source guarantee.
5. `--markdown` mode prints the inventory table for `docs/dependencies.md`.
6. Exit 0/1 with a per-file report.

### Env emission: `deps/scripts/catalog.env.sh`

Bash + awk only, so gap-side and plain-shell invocations need no Python. Parses the controlled TOML subset of `deps/versions.toml` (top-level `[versions]`/`[images]` sections, `key = "value"` lines, `{key}` interpolation inside `[images]`). Emits uppercased env vars:

```sh
source deps/scripts/catalog.env.sh
# CATALOG_VERSIONS_CAPI=1.14.0
# CATALOG_IMAGES_WORKLOAD_NODE=kindest/node:v1.35.0
```

`build-package.sh` also writes `airgap/archives/catalog.env` (gitignored dir, travels with the bundle) so `stage-and-create-cluster.sh` can source catalog values on the gap-side host where no repo, mise, or Python exists. `offline-run.sh` instead globs `zarf-init-arm64-v*.tar.zst` so it carries no zarf pin at all.

### Rendering: `deps/scripts/render.py` and `@@key@@` markers

- Templates: `airgap/zarf.yaml.in`, `airgap/images.txt.in` (plus a small `airgap/manifests/flux-instance.yaml` slot, validation-only since it is a committed capture).
- Markers `@@key@@` resolve against versions and composed images; unknown marker is a hard error (typo protection).
- `render.py` writes the sibling output file deterministically (single-pass substitution, no timestamps).
- `render.py --check` re-renders to stdout and diffs against the committed file: the drift gate.
- Rejected alternative: Zarf's own `###ZARF_PKG_TMPL_*###`. It defers resolution to `zarf package create --set`, which moves pins out of the reviewed file and out of the catalog. Committed generated output with a CI check gives both reviewability and enforcement.

### Manifests and CI: validation-only

Flux-synced YAML under `mgmt/` and `workload/` cannot read the catalog at reconcile time, and GitHub Actions cannot include external files. Both keep literal pins enforced by slots and `--forbid`. A future option (documented, not built): `postBuild.substituteFrom` a generated ConfigMap. Deferred because it changes what Flux reconciles and how konflate renders diffs; the issue explicitly allows validation instead of generation.

### mise and CI wiring

- `mise.toml` `[tools]` gains `python = "3.13"` (stdlib `tomllib` for check/render; determinism; air-gapped CI installs it via mise-action, no cluster impact).
- New tasks: `deps-check` (runs `python3 deps/scripts/check.py --forbid staged-rules`), `deps-render` (runs `render.py` then `deps-check`).
- `mise run validate` calls `deps-check` (and after PR 3, `render.py --check`) before the existing bash -n and kustomize loop.
- `.github/workflows/validate.yml` gains a `Dependency drift` step running the same checks with the runner's system python3 (ubuntu-latest ships 3.12).

## PR series

Six sequential PRs, each branched from `main` after the previous merges. Sequential-to-main (not stacked bases) is deliberate: konflate renders each PR against `main`, so every rendered diff shows exactly that PR's change, and CI gates each merge per repo policy.

Grouping follows the implementation, hardening, coverage progression: PRs 1-3 build the mechanism, PRs 4-6 extend enforcement to every remaining family and close the docs loop.

Every PR:

- Branch: `deps/62-<slug>` from updated `main`; never commit to `main`; no force-push; no `--no-verify`.
- Body starts with `Part of #62.` plus a short family list, the verification commands run, and their output summary. Drafted by the subagent, shown to the user for approval before `gh pr ready` (outbound text rule).
- Gates before push: `bash -n` on touched scripts, `mise run deps-check` (after PR 1 exists), `mise run validate`, and for validation-only PRs a `git diff main -- <manifests>` check confirming zero content change.
- Created with `gh pr create --draft --title ... --body-file ...` after pushing to `origin`.

## Subagent dispatch protocol

Run PRs strictly in order; each starts only after the previous PR merges to main and origin is fetched.

Per PR, one `delegate_task` leaf subagent with this context shape:

- goal: "Implement PR N per section 'PR N' of /Users/shrinedogg/knr-ops/.hermes/plans/<this-file>. Read that section and the Design section; do not improvise beyond them."
- context: repo path; instruction to `git fetch origin && git switch -c deps/62-<slug> origin/main`; AGENTS.md rules (never commit to main, mise run validate before push, update AGENTS.md only where structure understanding changes); the exact files and slot lists from the plan; verification gates to run and paste into the summary; commit message from the plan; `git push -u origin deps/62-<slug>`; `gh pr create --draft --base main --title <from plan> --body-file <drafted body starting "Part of #62.">`; return PR URL, body text, and gate outputs.
- Orchestrator (hermes) verifies each returned PR: fetch the branch, re-run `mise run deps-check` and `mise run validate` locally, inspect `git diff origin/main...` scope, confirm no unplanned files. Show the PR body to the user; on approval `gh pr ready` and request review. After CI (validate + konflate render) is green and the user approves merge, merge, then dispatch the next subagent.
- Subagents never approve reviews or post comments; all outbound GitHub text goes through the user-approval gate.
- Memory rules honored: work happens in the shared clone but on feature branches only (no worktree needed while strictly sequential; if parallelism is ever requested, switch to per-task `git worktree add ../knr-ops-deps-<n>`).

## Risks, tradeoffs, open questions

- **Determinism of rendered files:** mitigated by the idempotency gate in PR 3; any nondeterminism blocks that PR.
- **Slot regex fragility on reformats:** patterns anchor on the exact current YAML shapes; a reformat fails the slot loudly rather than silently passing, which is the intended direction of failure. Slot patterns are updated in the same PR as any reformat.
- **python 3.13 mise pin:** adds a tool install for all contributors; consistent with the repo's pinned-tools philosophy. Gap-side scripts never require it (env via awk script and catalog.env).
- **bootstrap.sh chart pinning (PR 2) changes behavior:** bootstrap currently floats to latest; pinning aligns it with what GitOps manifests deploy. Called out in the PR body for reviewer attention.
- **checkout v5 vs v7.0.1 across workflows:** kept as separate keys; a follow-up could unify, out of scope.
- **Open: pin `flux2`/`sops`/`age`/`aws-cli` (currently latest)?** Catalog records them as `latest` with a comment; actual pinning is a separate decision and PR.
- **Open: manifests via postBuild.substituteFrom?** Documented as future option; not built, per the incremental-delivery instruction.
- **konflate fork-PR skip:** all branches must live on `polarsquad/knr-ops` origin, which the plan assumes (user is core contributor with push access).
